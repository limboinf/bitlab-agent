# MCP 设置页 UI 重构设计

## 目标

在不改变 MCP RPC、配置格式或运行时行为的前提下，将现有设置页重构为更清晰的“连接器管理台”。页面继续位于“设置 > MCP”，借鉴连接器市场的卡片布局，但只展示 Bitlab 当前真实支持的服务器、发现结果和设置，不引入虚构市场目录。

## 页面结构

页面内容宽度从当前窄单列调整为适合双列卡片的宽布局，并保留现有设置页外壳和主题系统。

1. 页面标题区：标题、说明、搜索框、添加按钮。
2. 状态概览：已安装服务器数、运行中服务器数、可用工具总数。
3. 标签页：
   - **已安装**：展示服务器卡片，默认标签页。
   - **发现**：展示当前 Workspace 的 `.mcp.json` 和其他应用配置。
   - **全局设置**：展示审批、直接工具和默认生命周期设置。
4. 添加、编辑和删除继续使用现有对话框。

## 已安装连接器

服务器以响应式双列卡片展示，窄窗口降为单列。卡片摘要包含：

- 名称与来源；
- 运行状态；
- 传输摘要；
- 工具数量或需要登录、连接失败、已停用等当前状态；
- 启用开关。

点击卡片后在网格内展开详情。展开项横跨整行，同时最多只展开一个服务器，避免多个详情区造成页面过长和定位混乱。展开详情保留现有全部能力：

- 信任设置；
- 直接注册工具；
- 生命周期覆盖；
- 工具包含与排除规则；
- 来源路径；
- 测试连接及工具结果；
- HTTP OAuth 登录；
- 编辑与删除。

搜索按服务器名称、传输摘要和来源进行不区分大小写过滤。搜索无结果时显示局部空状态，不影响其他标签页。

## 发现与全局设置

“发现”标签页复用现有发现、批准、勾选导入和刷新逻辑，仅重新组织标题、空状态和卡片间距。“全局设置”标签页复用现有设置组件与即时保存行为。

标签页切换只改变客户端呈现，不重新请求列表。Workspace 变化时仍按现有逻辑重新执行发现。

## 状态计算

- 已安装：`servers.length`。
- 运行中：启用且最新状态为 `connected` 或 `cached` 的服务器数量。
- 可用工具：最新状态快照中启用服务器的 `toolCount` 之和；缺失值按零处理。

状态概览和搜索均由当前列表派生，不增加后端接口。

## 视觉与响应式

- 继续使用 Bitlab 现有颜色、圆角、阴影、字体、`SettingsCard`、按钮、输入框和语义变量。
- 不复制参考图中的品牌插画，不增加独立设计 token。
- 卡片使用克制的状态色；错误和待登录状态具有明确文本，不能只依赖颜色。
- 中等及以上宽度使用双列；空间不足时使用单列。展开详情始终占满当前网格宽度。
- 动画只用于标签内容淡入和详情展开，遵循现有时长与缓动。

## 错误与空状态

- 列表加载错误继续显示页面级错误提示。
- API 不可用、保存失败、删除失败、导入失败和 OAuth 通知沿用现有反馈。
- 已安装为空、搜索无结果、未发现配置分别显示对应空状态。
- 失败的服务器卡片直接显示失败状态；详细错误仍通过测试结果展示。

## 实现边界

- 主要改动限定在 `McpSettingsPage.tsx` 和中英文 MCP 文案。
- 不修改 MCP RPC、存储模型、运行时生命周期或发现规则。
- 不新增通用布局抽象；仅在页面内提取有明确职责且能降低复杂度的小组件。
- 保留现有添加/编辑 JSON、项目批准、跨应用导入、测试、OAuth 和删除流程。

## 验证

- Electron TypeScript 类型检查通过。
- 中英文 locale parity、排序和使用检查通过。
- 针对页面新增的纯派生逻辑进行测试，或在现有测试设施不适合渲染器组件时至少通过类型检查与人工交互验证。
- 人工验证：三标签切换、搜索、单卡展开、启用切换、测试、登录、编辑、删除、发现刷新/导入、全局设置和窄窗口单列布局。
